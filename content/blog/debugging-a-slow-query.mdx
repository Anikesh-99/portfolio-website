Every engineer eventually meets a bug that seems to defy physics. Mine was a
query that ran in 40ms all week and then took 9 seconds on Tuesdays.

## The investigation

The first rule of debugging: the machine is not being weird, *you* are missing
information. I started by capturing the query plan in both states:

```sql
EXPLAIN (ANALYZE, BUFFERS)
SELECT o.id, o.total
FROM orders o
JOIN customers c ON c.id = o.customer_id
WHERE o.created_at > now() - interval '7 days';
```

The Tuesday plan had switched from an index scan to a sequential scan. Why
Tuesday? A weekly batch import doubled the table's row count every Monday
night, and autovacuum hadn't caught up by morning — so the planner's
statistics were stale exactly one day a week.

## The lesson

The bug was never in the query. It was in the *schedule* around the query.
When something fails periodically, look for what else runs periodically.
