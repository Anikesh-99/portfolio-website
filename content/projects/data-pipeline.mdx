## The problem

Event data was arriving from a dozen sources with different formats, delivery
guarantees, and failure modes. Downstream teams needed a single, consistent,
queryable stream — and they needed to trust it.

## What I built

A pipeline with three stages, each independently deployable:

1. **Ingest** — source-specific adapters normalize events into a shared schema
2. **Process** — idempotent transforms keyed by event ID, so retries are safe
3. **Serve** — materialized views in PostgreSQL, refreshed incrementally

```python
@idempotent(key=lambda e: e.event_id)
def process(event: Event) -> Normalized:
    return Normalized.from_raw(event, schema=REGISTRY[event.source])
```

## Results

- 2M events/day with zero duplicate deliveries over six months
- New sources onboard in under a day via the adapter interface
- p99 ingest-to-queryable latency under 30 seconds
