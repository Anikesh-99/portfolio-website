Ask "what are the main risk factors in NVIDIA's latest 10-K, and how do they
differ from the prior year?" and the agent retrieves the relevant passages from
real EDGAR filings, reasons over them, and answers with citations like
`[NVDA 10-K 2025-02-26, Item 1A]` that you can verify against the source.

## Section-aware chunking, not fixed-size splits

The obvious approach is splitting each filing into 1,000-character chunks and
embedding them. I started there and retrieval was mediocre: a question about
liquidity would pull a chunk straddling the end of risk factors and the start
of MD&A, and the model couldn't tell where it came from.

10-Ks have a rigid "Item" structure, so I split on those headers first, then
chunk within each section. Every chunk carries its section label as metadata.
Two payoffs: citations point at "Item 1A" instead of "chunk 47", and queries
can be constrained to a section or ticker, which is also how the eval measures
recall.

## The eval came before the UI

In RAG, answer quality is mostly downstream of retrieval quality. If the right
passage never gets retrieved, no prompt saves you. So before building anything
user-facing I wrote an eval measuring recall@5: for a labeled question, did a
chunk from the expected (ticker, section) appear in the top five results?

![recall@5 by retrieval mode](/projects/sec-recall.svg)

Six rounds of measure-then-fix took the first run from 33% to 88.9%. Section
splitting alone moved it from 33% to 67%. The eval and the agent share the
same `retrieval.py`, so the number I tune against is the number the agent
actually gets.
